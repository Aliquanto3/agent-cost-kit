# Amélioration continue : limites vues en run autonome

Points relevés pendant les runs autonomes, avec leur contournement et ce qu'il faudrait changer dans le kit. Chaque entrée porte la source (projet et date). Une entrée traitée passe dans le `CHANGELOG` et sort de cette liste.

## Run WaveDevSecOps, nuit du 18 au 19 octobre 2026 (Windows, 3 stories en dev + revues en parallèle)

| # | Limite constatée | Contournement appliqué | Amélioration proposée pour le kit |
|---|---|---|---|
| 1 | La suite complète locale est passée de 7 à 60 min : 3 à 6 agents la lançaient en même temps sur le même poste Windows (git et serveurs réels, création de processus lente, Defender). La CI ubuntu faisait la même suite en 2 min 20. | La CI de branche sur les trois OS devient la seule suite complète ; agents et orchestrateur ne lancent que ruff et les tests ciblés ; tests lents marqués `slow` ; pytest-xdist ; exclusions Defender du dépôt et du cache uv. | `dev-story` et `reviewer` : « ne lance pas la suite complète locale si une CI de branche existe ; pousse et attends la CI ». Consigne globale « suite complète une fois à la fin » à nuancer : en run parallèle, c'est la CI qui la joue. `cost-kit-install` : proposer les exclusions Defender sous Windows. |
| 2 | Quota de l'API GitHub épuisé (403, limite secondaire) par une dizaine de `gh run watch` simultanés (intervalle de 3 s par défaut). | `gh run watch <id> --interval 60`, ou `gh run list` toutes les 2 min dans une boucle bornée. | Consigne dans `dev-story`, `reviewer` et le modèle de prompt d'orchestration : toujours `--interval 60`. |
| 3 | Branches empilées : des échecs n'apparaissent qu'à l'intégration (un test d'une story cassé par une autre, une garde de dérive qui découvre un scénario ajouté ailleurs, un nom de fait différent entre deux branches parallèles). | Empiler les branches revues, CI sur chaque branche de la pile, petit correctif d'intégration par l'orchestrateur ou un dev-story ; prévenir les agents en cours par message quand un contrat partagé se décide (`SendMessage`). | Modèle de `run-autonome.md` : section « Contrats partagés en cours » (noms, constantes) que l'orchestrateur tient et cite dans chaque prompt. |
| 4 | Le second avis et le reviewer lisent parfois une base périmée (branche partie avant une fusion), d'où des constats « high » déjà réglés sur main, ou des conflits de fond découverts tard. | Demander au reviewer de rebaser d'abord, puis de juger ; préciser dans le prompt ce que main contient depuis. | `second-avis` : comparer à `git merge-base HEAD origin/main` et signaler explicitement « base en retard de N fusions ». |
| 5 | Création de worktree refusée : dossier vide laissé par un `git worktree remove` en échec (fichier verrouillé sous Windows), puis lecture de `.git/config` pendant une écriture concurrente (`git push -u` des agents). | `rmdir` du dossier vide, `git worktree prune`, relance ; suppression des worktrees seulement en fin de run. | Orchestrateur : `git worktree prune` avant chaque lancement ; ne pas supprimer un worktree juste après la fin de son agent. |
| 6 | Push de `main` refusé de façon passagère pendant des pushes de branches simultanés. | Vérifier `main..origin/main` (rien de divergent), relancer. | Rien à changer ; noter le réflexe « comparer avant de forcer ». |
| 7 | Heures du journal estimées quand l'orchestrateur consigne plusieurs étapes d'un coup. | Toujours prendre l'heure par `date` au moment d'écrire ; une note signale les heures approchées. | `avancement-run` : signaler une ligne dont l'heure est postérieure au commit qui l'ajoute. |
| 8 | Commandes de plus de 10 min basculées seules en arrière-plan dans les agents (suite complète). | Consigne : lancer la suite en arrière-plan ou en lots, et attendre son résultat. | Devient sans objet avec le point 1. |
| 9 | `python` nu ouvre l'alias du Microsoft Store sous Windows. | `uv run python …`. | Commandes du kit et de `avancement-run` : `uv run python` par défaut sous Windows. |
| 10 | La consigne « Au plus 3 stories en développement » n'empêche pas 5 à 7 agents actifs (revues, rebases), ce qui charge le poste. | Compter aussi les rebases de fond comme du développement ; garder les places libres pour les stories du chemin critique. | Modèle de `run-autonome.md` : plafond global d'agents actifs (dev + revue), par exemple 5 sous Windows. |
