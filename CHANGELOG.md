# Historique

- **Non publié** : `avancement-run` suit les runs hors epics. Les identifiants alphanumériques de story (`C1`, `O4a`, `E1b`, `S3`, motif `[A-Z]{1,3}\d+[a-z]?`) s'ajoutent à `N.M` dans les cellules des vagues, les dépendances (seulement si ce sont des stories du run) et la colonne story du journal, jamais ailleurs (« v14 », « M1 » dans un résultat, heures et SHA ne comptent pas). Périmètre `| Dans le run | Stories C1 à C9, O1, O4a | … |` (plages de même préfixe développées), ou stories des vagues ; une story du périmètre absente des vagues va dans une vague « — ». Une story absente de `sprint-status.yaml` est suivie depuis le journal seul (`dev` lancé, `second-avis`, `review`, `fusion` = terminée, `blocked`, `attente humaine`) ; son titre vient de la liste `- C1 : titre` sous la table des vagues, à défaut de l'identifiant. Sans epic, le rapport n'a pas de tableau par epic. Rapport des numérotations en epics inchangé. Avant, un run hors epics donnait « 1/1 story terminée, 100 % ».

- **0.7.1** (2026-10-19) : `avancement-run`, deux incohérences relevées sur la story 5.7 de wavelocalai. Une story retenue par une `décision` ou un `report` est présentée avec cette raison (« 5.7 retenue par décision du journal (reportée après le run) ») au lieu de « attend la fin d'une autre story du même module » ; une story dont le `report` ou la `décision` dit explicitement qu'elle sort du run (« reportée après le run », « au prochain run », « hors run », « retirée du run », sans négation) sort du reste à faire, du débit, du chemin critique et de la date de fin : elle reste dans le total et le tableau, marquée « reportée, hors estimation », et « Attendu d'Anaël » dit « 5.7 reportée après le run (décision prise) » avec la suite demandée (« prévenir Anaël quand… »), sans la ranger parmi les décisions à prendre. Un `report` ou une `décision` sans sortie explicite (« attend 1.4 », « déplacée en V3 », « vérifier l'écran après le run ») retient la story mais la laisse comptée. Une story pas lancée qui dépend, même en chaîne, d'une story reportée sort aussi de l'estimation (« bloquée par 5.7 reportée », dans Points d'attention et Alertes). Une story relancée après un report redevient normale ;

- **0.7.0** (2026-10-19) : amélioration continue d'après trois runs autonomes (WaveDevSecOps, wavelocalai v2 MVP et Epics 5 à 8 ; `docs/amelioration-continue.md`). `avancement-run` : une story n'est « terminée » qu'une fois fusionnée (étape `fusion` ou « PR #n fusionnée ») ; nouvelle étape de journal `PR` (« PR ouverte », 93 %) ; `fusion master` (mise à jour de branche) et `fusion · refusée` ne comptent plus comme fusions ; vagues à suffixe (`V14b`) ; `second-avis · lancé` et `review · lancée` ne valent plus « fini » ; une `décision` ou un `report` retient une story ; le journal prime sur `sprint-status.yaml` quand il est plus récent, avec l'écart signalé ; médiane « PR ouverte -> fusion » et contrainte « fusions en série » dans l'estimation ; alerte goulot au-delà de 3 PR en attente ; heures du journal postérieures à leur commit signalées (`git blame`). Sur le run wavelocalai : 45 / 56 terminées, conforme au journal, au lieu de 44 / 54. Nouveau `scripts/file_prs.py` (file de fusion de PR : état lu d'abord, contrôles présents, `mergeable`, relance unique des jobs rouges, PR suivante au lieu de s'arrêter, `MERGED` vérifié, sondage d'au moins 30 s, `--a-sec`) ; `controle_rapide.py` décode les sorties en UTF-8 et compte toute erreur d'exécution comme un échec. Consignes : `dev-story` et `reviewer` laissent la suite complète à la CI de branche en run parallèle, `gh run watch --interval 60`, repli testé pour une dépendance native, jamais d'écriture dans le dépôt principal ; le reviewer rebase avant de juger et termine une fusion laissée en cours ; `second-avis` écrit le retard de base ; `uv run --no-project python` partout. Nouveaux `modeles/run-autonome.md` (contrats partagés, plafond d'agents, fichiers touchés par vague, sessions autorisées, état hors PR de story) et `docs/pieges-runs.md` ; `cost-kit-install` propose les exclusions Defender sous Windows ;
